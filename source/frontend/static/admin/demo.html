Demo mode. These buttons run real transactions on the database and show the rows read before and after. Run python database/reset_demo.py to start again with fresh data.
1

Check-out succeeds (COMMIT)

One transaction: lock bay + reservation → reservation Completed → work out fee → INSERT payment → INSERT outbox event → COMMIT.

2

Double booking is refused

Several customers press "Hold" on the same bay for the same time at the same instant. SELECT … FOR UPDATE makes them wait in line: the first wins, the rest are refused, and only one row is added.

3

Error half-way: ROLLBACK

Same check-out, but a failure is forced after the reservation is updated and before the payment is created. Every step is undone: the rows read after are identical to the rows read before.

4

MongoDB down: outbox keeps events, Retry sends them once

1. Switch MongoDB off · 2. Do something (scenario 1, or a booking) · 3. "Send queued now": events stay Pending (they wait, however long MongoDB is off; nothing is lost) · 4. Switch MongoDB on · 5. Retry: everything arrives once.
